# HyperDL v1.3.54

> **b13540** · full-zip release · changes since `v1.3.53`

Rebuilds the scraper recovery paths that dead endpoints had broken, pins the yt-dlp release with checksum verification, and fixes six WebUI bugs — the worst of which made open-file taps silently do nothing and delete actions report success on failure.

---

## Highlights

| Area | What changed |
| :--- | :--- |
| **Scrapers** | Dead endpoints replaced and recovery paths repaired so Facebook, X, and Instagram resolve again |
| **yt-dlp** | Extractor pinned to a verified release, checked on every build |
| **WebUI open** | Tapping a file now actually opens it — the button silently ran `status` before |
| **WebUI honesty** | Delete, cookie saves, and cleanup no longer announce success when the bridge failed |

---

## Repaired scraper recovery paths

- **Replaced dead endpoints.** Bilibili resolves through yt-dlp again after its direct API kept returning HTTP 412, because a fallback that always fails is worse than none.
- **Kept the requested format.** HLS remuxes that fall back to yt-dlp no longer discard the format the user picked, because a 1080p request silently delivering 360p is a bug, not a fallback.
- **Covered the regressions.** The recovery paths now have tests, so the next endpoint rot gets caught before release instead of after.

## Pinned yt-dlp with checksum verification

- **Pinned the extractor release.** `ytdlp.pin` locks the version to `2026.10.21` and the build verifies its checksum, because an unpinned fetch could pull an untested extractor overnight.
- **Re-resolved on every run.** The build gates on drift between the pin and what is installed, so a stale runtime is caught at build time instead of at download time.
- **Kept startup fast.** The pinned payload ships as optimized `.pyc`, benchmarked to load faster than the plain source.

## WebUI: open actions actually open

- **Fixed the dispatch bug.** `open` and `open_folder` were rewritten to `status` inside the bridge command builder, so every tap returned download status instead of opening the file. The feature had never worked.
- **Quoted the action too.** Paths were escaped but actions were interpolated raw, because the original builder only protected one of the two.
- **Distinguished real failures.** A missing binary, a path outside the download folder, and an empty response each get their own message instead of silence.

## WebUI: honest success and failure

- **Delete reports the truth.** A rejected path returns `success:false`, and a partial delete (two of three removed) now says exactly that instead of claiming all three, because the bridge answers `{"success":true,"deleted":2}` for partial work.
- **Cookie saves validate.** `decode_failed` and `open_failed` get distinct messages, and an empty response is treated as a failure rather than a save, because cookies are a live login session.
- **Cleanup and toggles verify.** Junk cleanup, notification mode, and vault-domain saves check the payload before claiming success.
- **The status poller cannot leak.** A bridge that stops answering stops the poll after roughly ten seconds and tells the user, instead of leaving a 400 ms timer running forever.
