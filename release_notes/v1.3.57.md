# HyperDL v1.3.57

> **b13570** · full-zip release · changes since `v1.3.56`

Refreshes the bundled yt-dlp to 2026.10.26, restores resolution lists on several progressive MP4 sites, and makes Reddit, Threads, TikTok, and Bilibili downloads report accurate titles and errors.

---

## Highlights

| Area | What changed |
| :--- | :--- |
| **Resolution picker** | Progressive MP4 sites list their qualities again instead of an empty picker |
| **Extractor** | Bundled yt-dlp moves to 2026.10.26, the latest release |
| **Reddit** | Titles come from the post URL instead of a generic mirror title |
| **Threads** | Video posts without `og:video` download through the post's embed page |
| **TikTok** | Owner-only videos explain why they cannot be downloaded |
| **Bilibili** | HTTP 412 blocks tell you what to try next |

---

## Resolution picker

- **Empty quality lists on progressive MP4 sites.** The probe dropped every format that yt-dlp reports without a codec field, so plain MP4 sources showed no qualities. Only an explicit `vcodec: "none"` now marks an audio-only stream.

## Extractor

- **Bundled yt-dlp moves to 2026.10.26.** The pin follows the latest release so the bundled extractor carries current site fixes. Sites that upstream still breaks stay unavailable until yt-dlp repairs them.

## Platform fixes

- **Reddit titles now match the post.** The rapidsave mirror returns one generic page title for every post, so the title is read from the Reddit URL slug.
- **Threads video posts download again.** Some video posts omit `og:video` from the public page, so the MP4 is read from the post's `/embed` page instead.
- **TikTok owner-only videos report the reason.** Videos set to "Only me" cannot be served by any fallback, so HyperDL now says so instead of failing in a fallback player.
- **Bilibili HTTP 412 explains the next step.** Bilibili's anti-bot check rejects automated requests, so the error suggests adding session cookies or retrying later.
